# 餐饮美食多平台社媒内容生产

从零到交付：理解产品 → 分平台创作 → AI生图 → HTML预览 → 查重校对。

## 触发条件

用户要求为餐厅/面馆/小吃店等餐饮商家制作社交媒体推广内容，涉及以下平台之一或多平台组合：
- 小红书（种草笔记）
- 微信公众号（长文推文）
- 抖音（短视频脚本）
- 微信视频号（温情故事）

## 核心流程

### Step 1: 信息采集

从用户提供的运营方案/品牌文档中提取：
- 店名、老板名、地址、营业时间
- 核心产品卖点（食材、工艺、口味、差异化）
- 品牌故事（创始人背景、坚持的理由）
- 目标人群（打工人、老乡、美食爱好者）
- 平台策略与内容调性

用占位符 `（待补充）` 标记未知信息，等用户确认后统一替换。

### Step 2: 分平台创作

#### 小红书 — 种草笔记

- 字数：150-300字正文
- 调性：口语化、大量Emoji、真实感
- 结构：情绪hook开头 → 产品体验描述 → 实用tips → CTA地址
- 话题标签：8-10个（#深圳美食 #宝藏小店 等）
- 配图：3-4张竖版3:4，封面为食物特写
- 预设2-3条评论区互动（含作者回复）

#### 微信公众号 — 长文推文

- 字数：1500-2000字
- 调性：专业但不枯燥，有人情味
- 结构：场景钩子 → 2-3节分述 → CTA结尾
- 标题备选：3个（不同角度）
- 配图：6-8张，每张配拍摄要点+可灵提示词
- 类型可选：产品科普型 / 人物故事型

#### 抖音 — 短视频脚本

- 时长：25-40秒
- 节奏：前3秒高能钩子 → 快剪卡点 → 慢镜头收尾
- 输出：分镜秒级表格（时间|画面|口播|字幕|备注）
- BGM建议：具体到曲风/曲名
- 拍摄要点：灯光、角度、收音细节
- 抖音文案区+评论区置顶文案

#### 微信视频号 — 温情故事

- 时长：60-120秒
- 调性：温暖、走心、适合私域裂变
- 结构：场景钩子 → 情感递进 → 产品融入 → 结尾引导
- BGM：纯音乐/钢琴
- 封面文案单独设计

### Step 3: 查重与去重

创作前先检查：
1. 用户是否提供了旧文案（附件/MyD盘/聊天记录）
2. 搜索历史会话中的相关内容
3. 运营方案文档中的"备用文案"段落

如果发现重叠：
- 标记撞车段落
- 用全新角度替换（如：原故事是"老乡否定"，可换成"冷启动0客流"、"学徒经历"、"食材溯源之旅"等）
- 确保每个平台的内容角度不相互重复

### Step 4: AI生图（可灵Kling）

参考文件 `references/food-kling-prompts.md` 获取完整的食物摄影提示词库。

#### 关键参数
- 模型：`kling-v1-5`
- 比例：小红书/公众号统一 `3:4`
- 负向提示词：`blurry, distorted, low quality, watermark, text, logo, oversaturated, cartoon`
- n=1

#### API调用要点
- 端点：`POST https://openapi.klingai.com/v1/images/generations`
- Auth：`Bearer api-key-kling-<完整Key>`（必须带前缀）
- 轮询：GET `/v1/images/generations/{task_id}`，通常8-20秒完成

#### 限流规避 ⚠️
- 可灵提交任务时**必须加延时**（≥0.3秒间隔）
- 单批建议 **≤9个并发任务**，超过会触发HTTP 429
- 被限流的任务等3秒后逐一补跑即可
- 提交失败≠生成失败，不要重新提交全部

### Step 5: HTML预览

为每条内容创建可在浏览器中直接打开的HTML预览页。

#### 小红书预览
- 420px宽手机卡片，圆角阴影
- 头部：头像+用户名+关注按钮（小红书红 #FF2442）
- 图片轮播：3:4竖版，左右箭头+圆点导航
- 互动栏：点赞（可切换❤️/🤍）+评论+分享+收藏
- 正文区：点赞数+文案+话题标签
- 评论区：2-3条模拟评论（含作者回复）
- 图片onerror降级策略

#### 公众号预览
- 680px宽文章布局，暖色调
- Hero头图：16:9比例，标题叠加
- 正文：h2分节标题（品牌色左边框），图片居中嵌入
- Blockquote：品牌色左边框引用块
- CTA：渐变背景信息卡片
- 参考配色：主色#E85D3A（食物暖橙），背景#FFFEFB

### Step 6: 信息回填

用户补充实际信息后，统一替换所有占位符：
- `[店名]` → 实际店名
- `[老板名字]` → 实际姓名
- `[详细地址]` / `深圳[区域]` → 完整地址
- `[营业时间]` / `[时间]` → 实际时间
- `[年数]` → 实际开店年数

用 `patch` 工具批量替换，`replace_all=true` 处理多处出现的占位符。

## 踩坑记录

1. **食物vs人像摄影**：`xhs-photographer-note` 的提示词模板是人像摄影，不适用于食物。食物提示词重点关注：食材质感、酱汁光泽、蒸汽动态、摆盘构图、暖色调。
2. **可灵限流**：并发>9个任务触发429，加延时逐批提交。补救：被限的任务等3秒后单跑。
3. **旧文案藏在运营方案里**：用户说的"旧文案"可能不是独立文件，而是运营方案docx末尾的"备用文案"段落，需要全文阅读再对比。
4. **占位符替换效率**：8个文件×多个占位符=手动patch太慢，用 `execute_code` 批处理更快，但需要用户批准。
5. **公众号标题也要改**：撞车时不仅正文要改，标题备选列表中的对应条目也要替换。
